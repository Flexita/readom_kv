# Voyage 首次测试与恢复方案（只写不执行）

**状态：** 提案。未授权清理、部署、安装或首次启动。  
**前提：** 云端已有 STAGING-NOT-INSTALLABLE 组件；**尚无**可执行 `Readom.sh`。在可执行入口与 C `identity_ready` 未就绪前，**不具备**向用户请求“现在就装上试”的条件；可请求的是后续授权议题的预审。

## 阶段

### 0. 云端准备（本轮范围，已部分完成）

- 校验 experimental system/ramdisk/data staging 哈希与产品标识。
- **停止条件：** 产品 prop 不是 voyage、稀疏/raw 不一致、或误产出 Readom 文件名 → 销毁该目录，不外发。
- **恢复：** 仅删云端 staging 目录；不触碰设备。

### 1. 用户确认清理（未授权，勿执行）

仅提议删除/移走**我们创建或明确无用**的文件，**不动书籍**：

| 候选（须用户点名确认） | 说明 |
|---|---|
| 我们创建的 `fill_disk`（或同等占位） | 约 1600 MiB 量级占位；**仅当用户确认路径与大小** |
| 无用的 `Hotfix.bin`（若存在且用户确认非越狱必需） | 与安装器无关的残留；**误删可能影响越狱恢复** → 必须用户确认 |

**实测空闲：** 探针 `available_1k ≈ 71792`（约 **70 MiB**）。  
**安装峰值（可证公式）：** system 512 + data 1024 + reserve 64 = **1600 MiB**（payload &lt; data 时）。  
**首启 dexopt 额外占用（估计，非实测）：** 另建议预留约 **256 MiB** 量级到 `/data` 侧增长；合计清出建议 **约 1856 MiB** 空闲作保守实验预算（**estimate**）。不能声称“1600 仍够”覆盖 dexopt。

**停止条件：** 用户未书面确认路径；或清完后 `df` 仍 &lt; 建议值。  
**恢复：** 不做自动删除；若用户已删，只能从其备份恢复书籍区（本方案不提供删书步骤）。

### 2. 首次 handoff（未授权）

需要：可执行入口（当前 **被拒**）+ C identity 填妥 + 用户显式授权。  
**停止条件：** E105 / `VOYAGE_INSTALL_BLOCKED`；bootmode≠main；MACH_TYPE 不符。  
**恢复（无需 Android 已工作）：** 入口失败应在写盘前或检查失败时回到书库；若已写 `android/` 下镜像，可按安装文档从电脑删除 `android/system.img` 与 `android/data.img`（**仅 Android 目录**）后点回书库。Voyage 上该路径 **unverified**。

### 3. Android 启动（未授权）

无 host dexpreopt：首启必做 boot.art + 应用编译，512 MiB RAM 下时长/是否 OOM **不可证**。  
**停止条件：** 长时间停在“正在启动 Android”后仍无桌面；或 watchdog 回原厂。  
**恢复：**

- 先等数分钟（dexopt 可能很长）。
- 文档中“按住电源约 40 秒回原厂”来自 **PW3/亚马逊通用说明**，在 Voyage 上 **未测**，**不保证不变砖**，不得写成 Voyage 已证实步骤。
- 若 USB 仍可出盘：从电脑删除 `android/` 下镜像（不动书籍）。

### 4. 回原厂验证（未授权）

确认书库、越狱 `.sh`、书籍完好。  
**停止条件：** 越狱入口丢失 → 按用户所用越狱的**官方**升级后恢复步骤（本仓库不替代）。  
**恢复：** 不自动重装越狱。

## 风险定性

首次测试是 **实验风险**，不是日常可用。Wi‑Fi、Voyage 触控、波形、恢复键时序均 **unverified**。完整可执行包未出前，不应请用户先清空间“以便马上安装”。
